PR1. Voice Quality Index (VQI): Utility-Based Voice Quality Assessment for Speaker Recognition

  • Dates: 2024 – 2026 · Role: lead researcher and developer (dissertation core) · Supervisor: Dr. Masudul Imtiaz; collaborator Dr. Stephanie Schuckers
  • Funding: FBI CJIS "Quality Checking and Enrolling High-Quality Voice Samples" ($108K), CITeR, NSF #2501916
  • Overview: ISO/IEC has standardized per-sample quality metrics for fingerprint, face, and iris, but not for voice. VQI is the first utility-based, explainable voice quality metric: it predicts how useful a recording will be for speaker verification and returns two 0–100 scores, VQI-S (signal quality) and VQI-V (voice distinctiveness).
  • Duties:
    • Defined the problem against the ISO/IEC 29794-1 "quality as utility" framework, and designed dual-score outputs that give actionable feedback (re-record vs. speaker limitation)
    • Built a large-scale data pipeline over 11 datasets (~2.6 M utterances; VoxCeleb1/2, Common Voice, LibriSpeech, VOiCES, VCTK, CN-Celeb, VPQAD, VSEA-DC) with MUSAN / RIR augmentation, 16 kHz resampling, VAD, and loudness normalization; parallelized processing of millions of files with Dask / PySpark and stored features in Parquet tables for SQL queries
    • Designed consensus labelling from 3 speaker-verification systems (ECAPA-TDNN, ResNet34-SE, ECAPA2) with s-norm over 1.2 M mated and 28 M non-mated pairs, producing a balanced 20,288-sample training set
    • Tried custom asymmetric objectives in XGBoost and LightGBM (custom gradient and Hessian) that penalize over-rating poor-quality samples more than under-rating good ones, since accepting a bad recording costs more
    • Ran large-scale embedding inference for labelling across multiple GPUs (PyTorch DistributedDataParallel, torch.multiprocessing) with batched, mixed-precision (FP16) inference, and tuned batch size and data loading to raise throughput
    • Wrote GPU code for pairwise scoring of millions of trial pairs (CUDA kernels via CuPy / Numba, batched matrix operations) and profiled bottlenecks with the PyTorch Profiler, NVIDIA Nsight, and py-spy
    • Engineered 705 explainable acoustic features (SNR, HNR, clipping, C50, bandwidth, F0, formants, harmonic richness, etc.) and a 3-stage selection pipeline (430 + 133 kept)
    • Benchmarked 8 model families (RF, Ridge, SVM / SVR, MLP, LightGBM, XGBoost, TabNet, LR) as classifiers and regressors with 5-fold CV and hyperparameter search; compared 7 dimensionality-reduction settings (PCA, FA, ICA)
    • Trained, evaluated, and versioned hundreds of model configurations concurrently (model families × targets × feature sets × folds) as SLURM job arrays and parallel workers, logged every run's metrics and artifacts to MLflow, and kept all 28 released models loadable side by side in the app with a shared inference and monitoring path
    • Clustered recordings by their acoustic features (k-means, DBSCAN, PCA / UMAP views) to find quality groups, and flagged anomalous recordings with Isolation Forest and robust z-scores before labelling
    • Evaluated with ISO/IEC Error-vs-Reject Curves, ranked DET, and dual-score quadrant analysis across 5 datasets and 5 providers, including held-out x-vector and WavLM-SV; analyzed emotion effects on the ESD corpus
    • Framed quality-based rejection as selective prediction (a reject option that flags inputs the system should not be trusted on): compared rejecting samples by VQI with rejecting by the verification system's own match-score confidence on Error-vs-Reject curves, and checked how well the scores were calibrated
    • Built and open-sourced a desktop app and CLI (record / upload, dual gauges, waveform and spectrogram, per-feature explanations, report export)
    • Generated plain-language feedback text for each quality issue with templates and LLM drafting, and tested readability with users
    • Added opt-in, anonymous usage logging to the VQI software (feature use, session length, GUI vs CLI and batch use, errors, and which quality feedback users saw), and combined it with GitHub release downloads and issue reports
    • Analyzed the software usage patterns (SQL, pandas, dashboards) to find where users got stuck and which quality problems were most common, and used the findings to prioritize improvements such as clearer feedback text, faster batch scoring, and a simpler install
    • Built real-time streaming audio in the app: full-duplex capture and playback with PortAudio / sounddevice callbacks, ring buffers, chunked VAD, and live quality scoring on short frames
    • Kept all audio processing and scoring on the user's own device (no cloud upload) for privacy, with local per-user enrollment so feedback adapts to each speaker (privacy-first on-device personalization)
    • Compressed the models for on-device inference: knowledge distillation of the ensemble into a compact student model, feature and tree pruning, and INT8 post-training quantization for fast CPU inference on ordinary laptops
    • Optimized end-to-end latency and throughput of the audio pipeline: vectorized feature extraction (NumPy, Numba), C++ extensions for hot loops (pybind11), a Rust prototype of the feature extractor (PyO3), multiprocessing for batch scoring, and model export to ONNX Runtime and TensorRT
    • Served the exported ONNX / TensorRT models and the speaker-embedding models on the lab GPU server with NVIDIA Triton Inference Server (dynamic batching, concurrent model instances, model ensembles for preprocessing plus scoring, gRPC and HTTP endpoints), and load-tested throughput and latency with perf_analyzer
    • Used LLMs (Claude Code, GitHub Copilot, ChatGPT / GPT-4o) for code generation, refactoring, debugging, unit tests, and documentation across the data pipeline, feature extractors, model-training scripts, and the desktop app / CLI
    • Used LLMs to draft plain-language, per-feature feedback messages for the app (what each quality issue means and how to fix it), then reviewed and edited them
    • Used LLM assistants for literature search and summarization, manuscript editing, and drafting responses to reviewers
    • Wrote the IEEE Access paper as corresponding author and handled peer review; presented at the ECE Graduate Seminar
  • Tech stack: Python, NumPy, pandas, SciPy, scikit-learn, XGBoost, LightGBM, pytorch-tabnet, PyTorch, SpeechBrain, Hugging Face, librosa, Praat / Parselmouth, torchaudio, Matplotlib; PyQt / Tkinter, PyInstaller; HPC / GPU; Git / GitHub; LLMs: Claude (Claude Code), ChatGPT / GPT-4o, GitHub Copilot
  • Highlights:
    • Developed the Voice Quality Index, the first utility-based voice quality metric that predicts speaker-verification performance, cutting false non-matches by up to 38% when the lowest-quality 20% of samples are rejected (IEEE Access, 2026).
    • Built an end-to-end ML pipeline over 2.6 M utterances and 11 datasets, from consensus labelling with 3 speaker-verification systems to 705 engineered features and 8 benchmarked model families.
    • Validated generalization on 5 datasets and 5 verification systems, including 2 never used in training, with ISO/IEC Error-vs-Reject and DET analysis.
    • Shipped an open-source desktop app and CLI with explainable, per-feature quality feedback (github.com/ahmedajan/VQI-v1).
  • Outputs: J1 (IEEE Access), T2 seminar, VQI software
